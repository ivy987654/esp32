# ESP32-S3 RGB 屏仪表盘 · AI 协作开发技能

来源：一个真实项目。正点原子 DNESP32S3（N16R8）+ ATK-MD0430R 4.3 寸 800×480 RGB 屏（GT9xxx 触摸），做成桌面黑胶歌词仪表盘 + 键盘屏 + 语音 AI 助手。第一版固件反复花屏，最后**从头重构**才稳定（40 分钟长测、3.7 万帧零坏帧）。本技能把重构版的做法和一路的教训整理成可复用的流程。

适用：任何 "ESP32-S3 + 16 位 RGB565 并口屏 + PSRAM 帧缓冲 + 电脑串口供数" 的项目。

---

## 一、核心结论（先读这五条）

1. **花屏先怀疑渲染，不是数据。** 本项目一度以为是串口缓冲在 PSRAM 里被破坏，最后用抓包（收到的帧全部正确）和 PSRAM 读写自检（0 错误）排除了，真正元凶是**每帧大面积重绘**：全屏旋转的唱片封面、滚动字幕。重构时从设计上去掉这两样，花屏就没再出现。
2. **零花屏优先于动画。** RGB 屏的帧缓冲在 PSRAM，屏幕 DMA 要持续读它，带宽很紧。不做大面积旋转、滚动、渐变、半透明、切屏动画。
3. **协议要能自证正确。** 帧头 + 长度 + CRC，大数据分块且整体再校验一次；电脑定时全量重发，丢帧能自愈。
4. **用板子的真实画面验收。** 不要只靠用户描述。让固件支持把帧缓冲经串口读回电脑，定时截图检查。
5. **长测再交付。** 至少 30～40 分钟、换多首歌（中英文），统计坏帧数，抽查截图，全部干净再交给用户。

## 二、协作原则

- **你是手，用户是眼。** 每次烧录后请用户拍照或描述。引导他说具体：哪个区域、显示了什么字、是横向撕裂、整屏闪白、重影还是板子在重启。
- **先最小可见结果。** 第一步只显示一张静态图，验证引脚、时序、PSRAM、烧录链路。
- **先复述再动手。** 语音输入的需求常有错字，先翻译成改动清单；参考开源项目时先列"借鉴哪几点、哪几点不适用及原因"。
- **一次只改一个变量。** 怀疑某功能，就刷一个"只去掉它"的测试版。
- **"更糟了"就回退。** 不在错误方向上叠加修改。
- **补丁打不完就重构。** 同一类问题修了三四轮还在复发，停下来整理需求和踩坑清单，新建工程（如 `dashboard2`）从架构上规避，旧工程保留作参考。
- **做不了的事给一行命令。** 权限拦截、按键、系统设置，给一行可复制的命令或一句明确操作，并说明预期结果。
- **密钥只放本地。** API key、WiFi 密码不写进代码、聊天、文档或仓库；放用户本机配置文件（如 `~/.<project>.env`），仓库只放 `.env.example` 空模板，回复中不回显。

## 三、推荐架构

```
电脑脚本 (Python, uv 运行)                         ESP32-S3
 ├ 正在播放 / 歌词 / 封面                            UART 接收任务 (core 1)
 ├ 天气                    ──二进制帧+CRC──▶          ├ 行/帧缓冲：内部 RAM
 ├ 麦克风→VAD→ASR→LLM→TTS   USB 串口 115200           ├ 封面分块→整图校验→替换
 └ 全局按键                                           └ 状态快照(加锁)
   单实例锁 + launchd 自启                            LVGL：只改变化的控件，局部失效
   发不出去：原地等待，不重连                          触摸：点卡片进详情，左右滑切屏
```

- 板子只管显示和触摸；网络、歌词、语音、大模型都在电脑上
- 时间由电脑同步（时间戳 + 时区偏移），断开后板子继续走
- 想把时间/天气挪到板子上走 WiFi 可以，但 WiFi 也吃 PSRAM 带宽，要重新做花屏长测；语音挪到板上需外接 I2S 麦克风和功放，且 Anthropic 等大模型接口只处理文字，听写和朗读要另接语音服务

## 四、开发流程

### 1. 环境与烧录
- PlatformIO，`framework = espidf`，`board = esp32-s3-devkitc-1`，16MB Flash，`flash_mode = qio`，自定义分区表
- 八线 PSRAM：`CONFIG_SPIRAM_MODE_OCT=y`，80MHz
- **`upload_speed = 115200`**（CH340 在 921600 下常报 `Unable to verify flash chip connection`）
- 第三方驱动报 `-Werror=...`：组件级加 `-Wno-error`
- **字体放单独分区**，平时只烧应用分区，烧录从几分钟降到约 1 分钟
- 卡在 `Connecting...`：按住 BOOT，点 RESET，松开 BOOT
- 烧录前停掉所有占串口的程序，包括自启服务（`launchctl bootout gui/$(id -u)/<label>`），烧完再 `bootstrap`

### 2. 引脚
- 引脚和时序**从厂商官方例程抄**，不要凭记忆
- 开工前列**引脚占用表**。RGB 并口占 16 根数据线 + DE + PCLK，板载 ES8388 音频的 I2S 与之冲突，不可用
- 要板上收音/发声：外接 INMP441 / MAX98357 到空闲 IO

### 3. RGB 面板参数（经验起点）
```c
.data_width = 16,
.clk_src = LCD_CLK_SRC_PLL160M,
.timings.pclk_hz = 16 * 1000 * 1000,   // 18MHz 出现撕裂，16MHz 稳定
.flags.fb_in_psram = true,
.bounce_buffer_size_px = LCD_W * 16,
```
- 数据 Cache 32KB、line 64B
- **单帧缓冲**。双缓冲两帧都在 PSRAM，本项目实测更闪

### 4. 界面设计约束（防花屏）
- 不做全屏旋转：封面在电脑端或启动时**静态合成**进唱片圆形里，不转
- 不做滚动字幕：长文本按宽度降字号、换行或省略
- 切屏、进详情页**不做动画**，直接切换
- 纯色平涂卡片，不要半透明、渐变、毛玻璃、阴影叠层
- 只更新内容变化的控件；label 的失效区域向外扩半个行高，避免字形超框留残影
- 像素非正方形要补偿：宽高比 =（物理宽/水平像素）÷（物理高/垂直像素）。本屏横向约宽 6%，圆形横向乘 0.944

### 5. 字体
- TinyTTF 运行时渲染一份 TTF 子集，支持多档字号
- 字体放 Flash（单独分区或 embed），**直接用映射地址读，不要拷进 PSRAM**
- 字形缓存设上限，别无限增长
- 子集覆盖 GB2312 + 繁体常用字 + 歌名歌手常见字（如"雲"）；电脑端可用同一份字表过滤
- 只用开源可再分发字体（霞鹜文楷、思源系列）；系统字体裁出的子集不能公开发布

### 6. 串口协议
- 二进制帧：帧头 + 类型 + 长度 + 载荷 + CRC，校验不过直接丢
- 大图（如封面 RGB565）分块发送，收齐后**整图再校验**一次才替换显示
- 板端接收缓冲用内部 RAM 静态数组，接收任务固定 core 1
- 电脑端每 ~10 秒全量重发；单实例锁（`fcntl.flock`）防两个进程同时写串口
- **串口发不出去时原地等待重试，不要关闭重开端口**：在 CH340 上反复开串口会拉 DTR/RTS 让板子重启，表现为"一直闪屏"

### 7. 数据处理（电脑端）
- 歌词：过滤 credits 行（作词、作曲、编曲、制作人、和声/合音等），按播放进度同步当前句
- 键盘监听：macOS 要给**实际运行的 Python 解释器**（uv 管理的 `~/.local/share/uv/python/.../bin/python3.x`）同时开"辅助功能"和"输入监控"，然后重启服务；密码框输入系统会屏蔽

## 五、调试方法论

1. **分段隔离**：绕过电脑脚本直接往串口发测试帧，区分"板子问题"和"数据源问题"
2. **收发对比**：板端打开调试，把收到的每一帧原样打印，与电脑发出的逐条比
3. **内存自检**：界面运行时在 PSRAM 上跑读写自检，排除内存损坏
4. **读回画面**：从板子读帧缓冲截图，检查实际显示，而不是只看日志
5. **读数字找线索**：`28800` = 东八区时区偏移秒数，`61%` 像湿度，`#152f` 像颜色值，可以据此判断哪两类消息串了
6. **二分功能**：关掉可疑功能（如旋转）出一个测试版
7. **看进程与链路**：`ps aux | grep <脚本>` 查多实例；烧录工具也连不上说明是 USB 线 / Hub 问题，不是固件

## 六、症状速查

| 症状 | 首先怀疑 | 处理 |
| --- | --- | --- |
| 烧录 921600 失败 | 串口芯片/走线 | 115200 |
| 官方驱动编译失败 | `-Werror` | 组件级 `-Wno-error` |
| 只有短消息能显示 | 两个进程抢串口 | 单实例锁，停掉多余进程 |
| 别的字段混进文本 | 丢字节/粘包 | 帧头+长度+CRC，全量重发 |
| 横向撕裂、文字重影 | 大面积重绘耗尽 PSRAM 带宽 | 去掉旋转/滚动/透明/动画；降 PCLK；bounce buffer |
| 双缓冲后更闪 | 两帧都在 PSRAM | 回退单缓冲 |
| 文字下方残影 | 字形超出 label 区域 | 失效区域外扩 |
| 圆形变椭圆 | 像素非正方形 | 横向乘宽高比 |
| 中文显示方框 | 字体子集缺字 | 补字重新生成 |
| 换大字体后界面乱 | 字体拷进 PSRAM 挤占内存 | 从 Flash 直接读，字形缓存设上限 |
| 长歌词溢出卡片 | 固定字号 | 按宽度降字号，必要时隐藏次要行 |
| 歌词显示"作词：xxx" | 没过滤 credits | 电脑端过滤 |
| 屏幕反复闪、连不上 | 脚本反复重开串口导致板子重启；USB 链路断 | 原地等待不重连；拔插线、直连电脑不走 Hub |
| 键盘屏一直是 0 | Python 没有输入监控权限 | 给 uv 的 python 开辅助功能 + 输入监控 |
| 板载麦克风无声 | 与 RGB 屏共用引脚 | 电脑麦克风 / 外接 I2S 麦克风 |

## 七、交付与部署

### 交付前
- [ ] 长测 30～40 分钟，换多首歌，坏帧数为 0，抽查读回截图无花屏、无串位
- [ ] 给用户一行烧录命令，写明波特率和烧录前要停的服务
- [ ] 开机自启（launchd plist）指向新脚本，路径是用户本机路径
- [ ] 源码、文档里没有 API key、WiFi 密码、私有接口地址；只有 `.env.example`
- [ ] `.gitignore` 排除 `.pio/`、`managed_components/`、`*.bin`、`*.log`、`*.env`、非开源字体
- [ ] 请用户拍照确认

### 换一台 Mac 部署清单
1. 装 Homebrew、`uv`，`brew install media-control`（读系统"正在播放"）
2. 拷整个工程目录（host 脚本要用里面的字体字表）
3. 用户**自己**拷 `~/.<project>.env`（含 key，不经过聊天）
4. 首次运行 `uv run <工程>/host/dashboard.py`：自动装依赖、下载语音模型；允许麦克风权限
5. plist 放进 `~/Library/LaunchAgents`，`launchctl bootstrap gui/$(id -u) <plist>`
6. 要键盘屏：给 uv 的 python 开辅助功能 + 输入监控，`launchctl kickstart -k gui/$(id -u)/<label>`
7. 板子不用重烧，串口自动查找
